## 一点五、这轮追加发现的最严重问题：滑点保护实际上形同虚设

- **位置**：`pkg/trade/swap.go` 的 `CalcMinAmountOutByPrice`
- **问题**：算完按滑点折算后的最小可接受输出量 `minOut` 之后，代码又多除了一次 1000：
  ```go
  //TODO: 零时处理下 /1000. 现在的计算逻辑更新了。
  minOut := tokenOut.Mul(AllBpDecimal.Sub(slipPageBP).Div(AllBpDecimal).Div(decimal.NewFromInt(1000)))
  ```
  注释自己都承认这是"临时处理"、"现在计算逻辑已经更新"——但那个 `/1000` 从来没删掉。对照同文件里姐妹函数 `CalcMinAmountOutBySwap`（走 AMM 储备量算法的那条路径）的正确写法，压根没有这个 `/1000`，公式应该是 `minOut = tokenOut * (10000-slippageBP) / 10000`。
- **影响面**：这个函数是 **Pump.fun 买卖 + Raydium CPMM + Raydium CLMM v1/v2 全部交易路径**共用的滑点计算入口（`pump.go:460`、`raydium.go:57,127,241`、`pkg/pumpfun/pump/buy.go:109`、`sell.go:43`），算出来的 `minAmountOut` 直接原样传给链上指令的 `OtherAmountThreshold`/`MinimumAmountOut` 字段。多除的这 1000 倍意味着**链上实际强制的最低成交量只有正确值的千分之一**——项目文档里主打的"滑点保护"这个核心风控机制，在所有交易路径上实际上等于没生效：用户理论上可以在被套利机器人打到只剩 0.1% 预期成交量的情况下，交易依然会被链上判定为"成功"。
- **修复**：删掉多余的 `.Div(decimal.NewFromInt(1000))`，改成跟 `CalcMinAmountOutBySwap` 一致的正确公式。

## 二、之前发现、现已修复的功能性 bug

### 1. 夹子（同块内既买又卖）过滤逻辑写了但没接线
- **位置**：`consumer/internal/logic/mq/claim.go` 的 `DetectClaim`
- **问题**：函数本身没问题（用位运算 `1<<0`/`1<<1` 判断同一 maker 在同一 block 内是否同时出现过 buy 和 sell），但全仓库搜不到一次调用，`trade.Clamp` 字段永远是 `false`
- **下游其实是等着这个字段的**：`dataflow/internal/logic/kline/calckline.go:98,198` 已经在读 `trade.Clamp` 来决定要不要把这笔交易算进开盘/收盘价——上游不置位，下游的过滤逻辑等于摆设
- **修复**：`consumer/internal/logic/sol/block/send.go` 里在 marshal 发 Kafka 之前插入 `mq.DetectClaim(trades)`

### 2. K 线实时推送到前端这条链路断在最后一跳
- **位置**：`websocket/websocket.go`
- **问题**：`BroadcastKlineUpdate`/`StartKlineSubscription` 整个文件从 import 到 `func main()` 全部被注释掉，是完全没编译过的死代码；真正在跑的 `token_websocket_server.go` 只处理"新币上线"频道，没订阅 `kline:updates`
- **修复**：把这部分能力迁移进真正在跑的 `websocket/token_websocket_server.go`：新增 `/ws/kline?pair_address=...&chain_id=...` 端点、`KlineClient`/`BroadcastKlineUpdate`/`StartKlineSubscription`，复用已有的、配置驱动的 Redis 客户端（没有引入新的硬编码连接）。删除了整个已死的 `websocket.go`

### 3. K 线分表命名缺年份 + 更深一层的"批次内随机选表"bug
- **位置**：`dataflow/internal/data/kline_mysql.go` 与 `market/internal/data/kline_mysql.go` 的 `TableName`
- **问题 A（缺年份）**：`fmt.Sprintf("trade_kline_%s_%02d", interval, ...Month())` 只拼了月份，2026-07 和 2027-07 会撞进同一张 `trade_kline_5m_07`
- **问题 B（更严重，藏在 `dataflow/internal/mqs/consumers/trade_consumer.go` 的 `saveKlineToDB` 里）**：每次 flush（500ms 或攒够 10000 条触发一次）会把同一 interval 的所有 K 线塞进一个 map，然后**用 Go map 遍历顺序里随便选中的最后一条 kline 的 candleTime** 去决定整批要写进哪张表。Go 的 map 遍历顺序是随机的，只要一批里混进了跨月甚至跨天的数据，就有一部分会被整体错误地写进不属于它的月表——不是"缺年份"这种可预期碰撞，是运行时随机性导致的真实错表风险
- **修复**：
  1. `TableName` 改成 `trade_kline_<interval>_<yyyy><mm>`（两处保持一致，读写不能对不上）
  2. `saveKlineToDB` 改成按 `(interval, 真实所属月份)` 分组，同一分组内所有 kline 才共享同一个 `candleTime` 去算表名，不再依赖 map 遍历顺序

### 4. market 服务里有一个"空转"的 Kafka 消费者
- **位置**：`market/internal/mqs/consumers/trade_consumer.go`（跟 `dataflow` 里同名但完全不同实现的文件撞名）
- **问题**：这个 consumer 真的订阅了 trade topic、真的会提交 offset，但函数体最后一行是 `// TODO: 根据交易数据生成 K 线并更新缓存`，从没调用过任何写入方法——是"接了线但白干活"，market 平白多背一个消费者组和一份 Kafka 拉取/反序列化开销，产出为零。真正生成 K 线、写 Redis/MySQL 的只有 `dataflow`
- **修复**：`market/internal/mqs/mqs.go` 的 `TradeConsumers` 直接返回空列表，注释写清楚为什么，代码原样保留供参考

### 5. CLMM 池子列表接口的核心指标是硬编码假数据（后续已实现一部分）
- **位置**：`market/internal/logic/getclmmpoollistlogic.go`
- **问题**：`LiquidityUsd`/`Txs_24H`/`Vol_24H`/`Apr` 四个字段永远返回 0，代码里写了 TODO 但没实现
- **已实现**：`Txs_24H`/`Vol_24H` ——确认 CLMM 成交的 `trade.pair_addr` 就是池子的 `pool_state`（见 `consumer/internal/logic/sol/block/raydium_clmm.go` 里所有 `trade.PairAddr = xxx.GetPoolStateAccount()...`），加了 `fetch24hStats` 按 `pool_state` 批量 join `trade` 表算最近 24h 的笔数和成交额，是真实数据
- **仍然没实现，而且刻意不造假**：`LiquidityUsd`/`Apr`——`clmm_pool_info_v1/v2` 这两张表从建表起就只存账户地址（vault、config 这些 PDA），从没存过任何储备量/余额数字，整条 pipeline 里也没有任何地方去抓 vault 的链上余额快照。没有储备量就没法算流动性，没有流动性也没法算 APR——这两个不是"还没写查询"，是**数据源头就不存在**，需要另外起一个专门抓 vault 余额的索引器才能做。留着 0 值 + 代码注释说明原因，没有编一个假数字充数

### 3. `market-local.yaml` 的 Redis 配置 key 名写错，本地开发从来没真正连上过
- **位置**：`market/etc/market-local.yaml`
- **问题**：yaml 顶层写的是 `Redis:`，但 `market` 的 `Config` 结构体要求的字段是 `json:"BizRedis"`；本地跑 `market -f etc/market-local.yaml` 会直接报错 `"BizRedis" is not set` 退出——这个本地配置文件从写出来那天起就没在本地真正跑通过
- **修复**：改成 `BizRedis:`

### 4. consumer 的 Kafka 生产者硬性要求 SASL 用户名密码，本地/无认证环境完全没法用
- **位置**：`consumer/internal/logic/mq/producer.go` 的 `NewKafka`
- **问题**：不管有没有配置 SASL，`username == "" || password == ""` 直接判失败返回 `nil`，consumer 就再也发不出任何 Kafka 消息——对本地 docker-compose（没开 SASL）或任何轻量演示环境是硬阻塞
- **修复**：新增 `newPlaintextProducer`，SASL 用户名密码为空时走无认证的 plaintext 连接，不再硬性要求

### 5. 本地开发缺 `docker-compose.yml`，README 引用的 `docker/` 目录在这份代码里根本不存在
- 已在 `docker/docker-compose.yml` 补上 MySQL 8 / Redis 7 / Kafka（KRaft 单节点，`apache/kafka:3.7.0`）三件套，密码等对齐各服务的 `*-local.yaml`
- **踩的一个坑记录一下**：MySQL 容器端口如果直接映射成 `3306:3306`，在很多开发机上会被本机已经在跑的原生 MySQL（比如 Homebrew 装的）在 `127.0.0.1:3306` 抢先绑定，Docker 的端口转发对 loopback 地址会失效，报错是"密码错误"而不是"连不上"，非常容易误判成密码配置问题。改成 `3307:3306` 并同步改了 4 个 `*-local.yaml` 的端口

## 五、本地开发怎么跑起来

```bash
cd docker && docker compose up -d   # 起 MySQL(3307)/Redis(6379)/Kafka(29092)，自动建表+灌种子数据
cd ../market   && go run market.go   -f etc/market-local.yaml
cd ../trade    && go run trade.go    -f etc/trade-local.yaml
cd ../consumer && go run consumer.go -f etc/consumer-local.yaml
cd ../dataflow && go run dataflow.go -f etc/dataflow-local.yaml
cd ../gateway  && go run gateway.go  -f etc/gateway-local.yaml
cd ../websocket && go run token_websocket_server.go -f etc/websocket-local.yaml
```

种子数据是纯虚构的（10 个 meme 币名字 + 随机游走的价格），不是真实链上数据，仅用于本地演示/面试展示交易列表、K 线图表长什么样。
